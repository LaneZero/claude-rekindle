# ClaudeRekindle v2.5.0-beta.1 — Reliability baseline

## Changes
- A single `src/core/detection.js` is used by Chrome and Firefox to identify Claude's warning banners and their *own* Continue button.
- Added browser-profile-wide arbitration: before clicking, a content script requests a claim from `background.js`. Concurrent claims are serialized, persisted in extension storage and denied on messaging failures.
- Usage-pause attempts have a 10-minute per-conversation cooldown; early-response attempts have a 15-second cooldown and a cap of three claims per hour per conversation. These are conservative safety limits, not guarantees against all duplicates.
- Added sanitized fixtures for observed pause, early-end and variable-percentage advisory messages.
- Added a simulated simultaneous-tab test and an optional headless Chromium DOM smoke test.

## Important limitations
- The Tampermonkey distribution still uses the legacy engine. Cross-tab arbitration applies to the Chrome/Firefox extensions only, and only within the same browser profile. Do not run the userscript simultaneously with either extension.
- A successful claim and `button.click()` are not proof the AI response completed. The prior `confirmed` label only means the warning banner cleared.
- Chrome and Firefox packages are **beta** and have not been tested against a live logged-in Claude session. Firefox Android remains experimental.
- Claims persist for up to one hour; multiple browser profiles/devices do not coordinate.
- A browser that is fully closed cannot run a normal extension; reset reminders run on the next browser start.
- No quota bypass, no cookie capture, no AI conversation text storage, and no direct Claude API requests.

## Local verification
```powershell
npm run check
npm run test:browser
```
The second command requires Chromium to be installed and on PATH, or `CHROME_BIN` to point to its executable. It is not part of the default CI because headless launch support varies by environment.

## Testing checklist
1. Pause banner, enabled Continue: exactly one click in the same browser profile.
2. Same paused chat in two tabs: only one claim accepted concurrently.
3. Early-ended response: clicks without waiting for a quota reset.
4. Percentage advisory: never clicks Upgrade/Dismiss or other buttons.
5. Disabled Continue: no clicks.
6. Close browser and reopen: saved reset reminder can reappear when due.
7. Firefox Android: separately verify permissions, storage persistence, alarms and notifications.
